# 原型开发路线与功能范围

版本：0.1；日期：2026-10-26。项目采用渐进完善的原型法。阶段名称表示验收边界，不代表日历工期。P0/P1 已在 v0.1.0 完成人工实机验收；P2 已在 v0.2.0 完成人工实机验收；P3 正在交付 0.3.0 本地候选并等待人工实机验收，其余阶段按以下边界逐步实施。

## 1. 开发方法

每轮遵循：选择一个可见使用场景 → 明确行为与接口 → 实现纵向闭环 → 自动验证 → 实机体验 → 记录问题与设计修订 → 达标后扩展下一轮。

可以保留已验证的原型代码，但不能将临时 mock、硬编码角色路径或绕过调度的测试按钮当作正式实现。验证 Windows 透明窗口、音频回调等不确定问题时允许建立短期技术实验；实验代码是否进入主实现必须单独判断。

原则尽早稳定，界面和参数逐步完善。稳定边界包括角色实例身份、非抢占语义、资源引用、包兼容规则、能力服务和渲染接口；不必在首轮做完所有设置页。

每轮交付必须同时给出可运行结果、配置/素材、验证记录和已知限制。不能用“页面已经画好”代替插件实际生效，也不能用“模拟器通过”代替系统全屏和媒体实测。

## 2. 阶段与完成定义

| 阶段 | 主要问题 | 可操作交付 | 完成定义 |
| --- | --- | --- | --- |
| P0 | 协议和调度是否自洽 | 样例包、校验器、假时钟调度演示 | 核心规则可确定复现 |
| P1 | 新宿主能否独立运行 | 离线桌宠、导入、规则插件和播放 | 离线端到端闭环通过 |
| P2 | AI 与角色隔离能否接入 | 人格、流式回复、TTS、两实例和导出 | 用户认可的七项最小闭环全部通过 |
| P3 | 默认功能是否完整 | Ema 行为插件与既有 AI 功能 | 完整默认功能目录可使用 |
| P4 | 普通用户能否制作和分发 | 制作工作台、表单、主题、完整包更新 | 不改源码完成角色与规则插件制作 |
| P5 | 日常使用是否可靠 | 性能、故障恢复、安装与升级 | 完整发布验收通过 |
| P6 | 接口能否支持更广扩展 | 隔离代码插件及新渲染后端 | 各扩展按独立标准验收 |

P1 是可体验的离线原型；P2 才是本次约定的完整最小验证。P3—P5 共同构成首个全面功能版本。P6 不阻塞序列帧正式版本，也不能以接口预留冒充已经支持 Live2D、3D 或多角色同屏。

## 3. P0：协议、素材和调度实验

### 3.1 输入

使用本设计文档、现有 Ema 素材、此前 AI 功能记录。首先核对实际文件和资源描述，不根据旧聊天印象猜测尺寸、时长和动作名。

### 3.2 开发任务

1. 在本目录建立全新工程边界，记录技术选择 ADR，锁定基础工具链和包管理方式。
2. 建立 contracts 与正反测试夹具，实现角色包、插件包、资源描述、规则和任务校验。
3. 编写独立 Ema 资源审计/转换工具，输出资源 ID、源文件、尺寸、帧数、播放方向、语音时长、缺失项和转换目标。
4. 实现不依赖 UI 的调度器、取消令牌、假时钟、开始授权、完成聚合器和基础姿态求解器。
5. 用内存通道模拟文字、声音和动画，确认整条任务完成后才交接。
6. 确认包格式的兼容结果、未知记录保留、配置删除和实例身份语义。

### 3.3 最小演示

低优先级任务先开始，过程中同时提交高优先级任务和基础姿态请求。观察低任务完整结束，再按优先级和入队顺序处理。另一个演示让低任务仍在准备，高任务先获得呈现权；晚到结果不能直接播出。

### 3.4 退出标准

- 调度顺序、开始/完成、用户取消、TTL 和全屏进入后又退出等案例可重复通过。
- 正常包、未知插件包和损坏包得到不同且正确的结果。
- 确认技术栈能够支持计划的透明窗口与音频控制，不能只完成依赖安装。
- 核心接口与 JSON 示例同步；不再依赖旧 TrayBuddy 状态机。

对应验证：PKG-01—07、SCH-01—12、BAS-01—04、CFG-01—03 的离线部分。其余实机内容留在对应阶段复验。

## 4. P1：离线桌面垂直闭环

### 4.1 范围

建立新的桌面应用，可载入新格式 Ema 包、持续播放 idle、执行有限动作，并通过独立气泡、输入框和音频通道呈现固定回复。

初期允许简单设置页和内部测试面板；普通使用行为仍必须经过统一任务链路。测试按钮只能发合法事件或请求，不能直接调用播放器绕过调度。

### 4.2 开发任务

- 实现序列帧渲染器、窗口锚点、透明背景、拖动、缩放和基本多屏边界处理。
- 实现普通文本及分页气泡、固定音声、有限动画的任务完成协议。
- 实现规则插件安装、角色配置、启停、优先级设置和诊断。
- 内置固定启动问候、全屏安静、媒体基础姿态三种插件。
- 从独立 .ayplug 安装“23 点提醒”，通过编辑触发时间或模拟时间测试。
- 加入真实全屏与媒体事实采集；宿主缺少某能力时显示可解释状态。
- 建立角色包最小导出：有效配置与资产打包、未知插件保留。

### 4.3 关键实机场景

Ema 正在播放有文字和语音的问候时打开全屏应用。现有问候完整结束，后续主动互动受到抑制，再进入 quiet。退出全屏时，如果媒体仍播放则回 music，否则回 idle。

同一条回复内文字先结束、音声后结束或动作最后结束，均只在全部有限通道完成后交接。循环 idle 不阻止下一条回复开始。

### 4.4 退出标准

新应用不需要启动 TrayBuddy 即可运行；23 点插件导入前后宿主二进制不变；真实检测、固定呈现与姿态恢复通过；失败导入不影响当前角色。

对应验证：PKG、SCH、BAS、REN、UI 中标记 P1 的用例。此时不宣称统一 AI 或记忆隔离已经完成。

## 5. P2：AI、语音和完整最小验证

### 5.1 开发任务

1. 实现服务提供者配置与独立凭据存储，统一角色人格、角色名、用户称呼和音色绑定。
2. 接入一条实际可用的聊天服务、一条实际可用的 TTS 服务及本地上下文存储；服务可关闭。
3. 支持 fixed、generated、generated-with-fallback，以及语音关闭、缺失素材与生成失败的清晰降级。
4. 实现流式文本、多页阅读、分段音声及完整任务收尾，实测 text-first 与 speech-synchronized。
5. 实现角色实例创建、切换、更新模板引用；两个实例可以复用同一份 Ema 图像，但配置和记忆必须独立。
6. 接入 Hindsight MemoryProvider；具备条件时使用独立测试 bank 验证真实请求。未接通实服务时只能标记本地隔离通过，不能标记远端隔离通过。
7. 实现有界摘要、同步 outbox、实际呈现记账和遗忘代次，确保异步回调不会跨角色写入。
8. 完成最小导出往返和本地覆盖编辑，保留未知插件条目与资源。

### 5.2 七项最小验证闭环

| 编号 | 演示 | 验收证据 |
| --- | --- | --- |
| MVP-1 | 新应用加载新 Ema 包，待机与多个动作播放 | 新进程、资源清单、画面和完成回执 |
| MVP-2 | 气泡、输入框、固定音声各自独立 | 纯文字、纯音声、纯动作和组合任务 |
| MVP-3 | 启动问候可选固定或统一人格生成 | 人格修改同时影响聊天和问候 |
| MVP-4 | 导入 23 点规则插件，无需改宿主 | 导入前后程序构建标识一致；规则实际触发 |
| MVP-5 | 全屏与媒体同时存在时正确恢复 | 正在说话不中断；最新有效姿态生效 |
| MVP-6 | 两角色实例配置与记忆隔离 | 各自历史、摘要、bank、音色和晚到回调记录 |
| MVP-7 | 编辑、删除素材，导出再导入 | 有效配置一致，未知插件及资源仍在 |

另需通过高优先级不打断已开始整条回复、同级 FIFO、主动停止和取消后不复活的调度验收。这是贯穿所有演示的约束，不是额外可选功能。

### 5.3 退出标准

七项闭环都有可复现证据；至少完成一次真实 AI 和 TTS 运行；本地隔离与远端隔离分别给出结论。未配置的服务不影响离线功能。用户能评价陪伴体验，并据此确认阅读停留、发送新消息策略和同步策略的默认值。

对应验证：MVP-1—7、AI-01—09、MEM-01—10、SCH 全部基础项、CFG-01—06。

## 6. P3：完整默认行为与已有 AI 功能

### 6.1 默认行为插件目录

以下 ID 为建议命名，正式锁定于 contracts。所有插件都遵守“无角色配置默认关闭”。默认安装不代表强制启用；Ema 测试包可提供用于验证的推荐配置。

| 插件 | 行为 | 主要可调参数 | 缺少角色素材的行为 |
| --- | --- | --- | --- |
| ayase.startup-greeting | 应用启动或明确选择的设备事件问候 | 事件来源、时段、每日去重、内容模式、音声、语义动作 | 可只显示文字；无动作保持基础姿态 |
| ayase.work-reminder | 长时间工作与休息提醒 | 统计口径、阈值、间隔、休息判定、冷却、响应 | 无专用动作也可提醒 |
| ayase.fullscreen-quiet | 其他应用全屏时抑制新主动互动并请求 quiet(如果存在多个显示屏，只针对当前桌宠所在的显示屏进行检测) | 检测范围、应用排除、基础模式、优先级、抑制范围 | 无 quiet 使用 idle，抑制仍生效 |
| ayase.media-response | 根据媒体播放申请 music 等模式 | 来源过滤、播放/暂停、进入退出、模式、优先级 | 无 music 保持 idle |
| ayase.random-interaction | 随机固定或 AI 互动 | 间隔范围、权重、时段、冷却、每日限额、内容变体 | 支持纯文字或纯声音 |
| ayase.scheduled-reminder | 固定时刻或周期提醒 | 时间、时区、重复、有效期、错过策略、回复 | 无模型专用素材仍可运行 |
| ayase.pointer-interaction | 点击等用户交互，可按需求启用 | 命中区域、点击方式、语义动作、回复 | 缺少区域可用模型整体区域 |

全屏安静与提醒休息属于不同插件。前者响应环境，后者主动提醒。媒体进入循环、暂停和恢复应由基础姿态请求表达，不能重现旧模型业务状态机对播放器的直接控制。

工作统计需要解释口径；“应用运行了多久”不能以“你持续工作了多久”的文案呈现。提醒后的休息恢复依赖明确条件，而不是播放一次睡眠动画就推断用户已休息。

### 6.2 AI 功能目录与服务边界

| 功能入口或插件 | 用户可配置内容 | 复用服务与状态 |
| --- | --- | --- |
| 聊天入口 / ayase.chat | 开关、发送策略、流式与朗读策略 | 统一人格、上下文、搜索选择、记忆与 TTS |
| 手动屏幕问答 / ayase.screen-question | 选屏或采集范围、是否附图、观察有效期 | 屏幕采集、视觉服务、统一角色回复 |
| 定时观察 / ayase.observation | 间隔、时段、触发条件、是否主动回复 | 观察存储与摘要；最终发言统一调度 |
| 联网搜索能力与入口 | 自动/手动搜索、提供者、超时、引用展示 | 搜索与事实上下文；最终回复统一人格 |
| 天气关怀 / ayase.weather-care | 地点来源、阈值、时段、冷却和内容模式 | 天气事实、日历、角色回复 |
| 日历关怀 / ayase.calendar-care | 时区、日期源、节假日/工作日条件、限额 | 环境快照、日历服务、角色回复 |
| 特殊日期 / ayase.special-date | 日期列表、循环规则、称呼、回复 | 时间服务、独立实例的相关资料 |
| 作息关怀 / ayase.routine-care | 时间窗口、设备活跃条件、冷却、限额 | 环境事实与独立实例上下文 |
| 记忆设置页 | 是否启用、保留/遗忘、同步状态 | 本地历史、摘要、Hindsight provider 与 outbox |
| 语音与音色设置页 | TTS 提供者、音色、语言、翻译、语速 | voice.synthesize、翻译服务、角色音色绑定 |

记忆、搜索、翻译和 TTS 的底层是通用服务，不要求为每次调用额外启动一个竞争发言的行为插件。需要独立用户入口时再提供对应插件；例如搜索后的回答仍属于原聊天任务。

现有 Fish 音色管理能力可作为 VoiceProvider 的一项实现，包括本地音色素材整理、试听、显式上传/创建音色、列表与角色绑定。创建结果固定写回发起该操作的角色实例或其指定服务库，不能在切换角色后绑定错人。

长上下文实现应保留连续对话、摘要水位、原文可追溯性和观察引用。查询旧屏幕与查询当前屏幕要区分。内部 reasoning 字段、工具 JSON 和技术错误不进入气泡正文或朗读。

### 6.3 共同配置和执行原则

每个行为插件提供事件来源、条件、优先级、冷却、去重、有效期、固定/AI 回复、语义动作、音声模式和状态诊断等适用字段。参数不适用时可以隐藏，而非强迫每个插件携带相同空字段。

所有用户可见 AI 发言从一个角色人格生成。观察提取和记忆整理使用内部任务提示词，不让多个插件持有互相冲突的人格。

多个关怀插件使用同一环境快照和全局主动互动预算；具体业务状态留在各自插件中。需要避免同一事实产生多条重复提醒，可通过语义去重键和全局冷却治理，不以中断当前回复解决。

旧工程中的阈值、45 分钟间隔、每天次数或“输入即取消”等规则只作历史参考。尤其自动取消已经被新的非抢占原则替代。新默认值需记录为配置并通过体验验证。

### 6.4 退出标准

默认目录每项功能都能单独启停、调整、模拟触发和实机触发；服务不可用有明确状态；所有输出仍通过同一调度与人格入口。环境采集、天气/日历、搜索、截图和远端记忆分别有真实集成证据，不能用假数据宣称完整可用。

对应验证：FEAT-01—10、AI、MEM、ENV、PLG 的 P3 用例。

## 7. P4：制作工作台与完整分发

### 7.1 用户流程

1. 新建角色，导入常规形态；单图即可，更多动作以后补充。
2. 配置角色名、称呼、人格与语义动作映射。
3. 按插件选择启用项，可全部跳过；逐项设置条件、文字、音声和动作。
4. 导入新规则插件；使用其 schema 自动呈现编辑页面。
5. 用虚拟时间和模拟环境预览，可单独启用真实服务测试。
6. 查看校验结果和发布内容，导出 .ayase。
7. 在宿主导入，修改本地配置，再导出验证往返。

工作台与日常宿主在界面复杂度上区分，但共享实现。初期可先做应用内独立工作台页面，再独立发布，不必首日维护两个重复应用。

### 7.2 工作台功能

资源库支持预览、重命名、替换、引用追踪、删除检查；回复列表支持一组文字、声音、动作配对；动作可按语义选择而不是输入内部文件名。

插件编辑器支持条件、时间、固定或 AI 回复、参数校验、导出规则插件。复杂规则提供高级模式，同时保留常见日程模板。代码插件编辑器不属于本阶段强制目标。

角色编辑提供基础模式和有限动作的独立预览、显示尺寸和锚点检查、缺失资源提示、配置差异、恢复推荐值。未知插件配置显示为保留的未启用条目，可在安装插件后继续编辑。

主题编辑支持颜色、九宫格图片、尾巴和文字布局；预览必须包含中文长句、短句、多页文本与缩放，防止只能显示一张漂亮静态图。

包更新提供合并预览和回滚；用户删除的音声不能更新后复活。导出不包含实例记忆和本机凭据。

### 7.3 退出标准

未修改宿主代码，完成新建角色、制作 23 点插件、导出、导入、调整和再次导出。工作台与宿主的同一配置结果一致。删除和未知插件往返、包升级和资源冲突都有验证证据。

对应验证：STU-01—07、CFG-04—08、PKG-08—12、UI-05—07。

## 8. P5：日常可靠性与发布验收

### 8.1 可靠性

验证网络超时、流中断、TTS 失败、音频设备切换、媒体事件抖动、全屏快速进出、插件异常、应用崩溃和重启。失败只清理受影响任务与资源，不使其他角色实例或插件配置丢失。

验证 Windows 锁屏、睡眠恢复、系统时钟跳变、时区改变、重启后错过提醒策略。操作系统造成的暂停与用户主动取消分别记录。重启不得重放旧任务残留的声音。

### 8.2 性能和桌面体验

建立不同角色资源大小、分辨率、DPI、显示器数量和显示刷新率的基线。测量 idle/动作/AI 准备/全屏安静时的 CPU、GPU、内存、耗电趋势、首帧时间、切换时间和停止响应。

优化必须不破坏业务时钟、全部文本可读、调度顺序和角色隔离。可降低静态姿态重绘、复用纹理和按需解码，但不能靠丢弃后半段回复或停掉提醒计时降低消耗。

具体性能阈值应在 P1 测得基线后写入验收记录，再在 P5 锁定；当前不伪造帧率、内存或响应时间承诺。

### 8.3 分发和升级

提供独立应用标识、应用数据目录、安装包、文件关联、退出与自启动设置、版本显示及诊断导出。升级数据库和包协议前备份可回滚状态；应用卸载与删除角色数据的关系明确展示。

从旧 TrayBuddy 自动迁移全部个人数据不属于首版隐含目标。需要时单独定义迁移器、字段映射和验证，不能直接共用旧数据库或应用目录。

### 8.4 退出标准

P3 默认功能、P4 制作分发以及[验收方案](04-verification.md)中的发布必要用例全部通过。关键隔离与完整播放问题无未解决缺陷；未测平台和未接服务明确标记，不能作为已支持能力发布。

## 9. P6：后续扩展

各项独立规划，不要求一次完成：

- 代码插件：隔离执行、SDK、资源配额、错误恢复、能力协商与升级兼容。
- 分件模型：贴图、遮挡补画、网格、枢轴、层级和物理参数；使用相同任务接口。
- Live2D：模型、纹理、物理、动作与表情的资源描述和能力映射；验证 SDK 集成和分发条件后再交付。
- 3D：模型、材质、骨骼、动作、相机、灯光和渲染预算；不强迫所有 3D 能力套进序列帧字段。
- 多角色：多窗口布局、每实例前台任务、共享音频仲裁、输入目标与提醒归属；保留现有记忆隔离。
- 角色素材辅助生成：参考图 → 资产生成 → 一致性检查 → 必要加工 → 模型描述 → 实机预览；不能把生成图自动当成经过验证的完整动画。

只有第二种后端实际运行同一行为插件且无需插件重写，才能认定渲染解耦得到跨类型验证。单纯保留接口只证明设计意图。

## 10. 测试素材准备与复用

### 10.1 Ema 转换清单

原型素材从现有项目读取，转换输出和测试包写入 AyaseCompanion。源文件保持可追溯；测试素材不自动成为公开发布内容。

| 原内容类别 | 新系统位置 | 转换方式 |
| --- | --- | --- |
| idle 及其他图集 | 视觉资产与 sprite 描述 | 保留帧顺序、透明度、尺寸和方向 |
| 问候、互动动作 | semanticCues | 映射 greeting、reminder 等语义 |
| 休息、媒体进入/循环/退出 | baseModes | 拆分有限过渡与持续循环 |
| 固定音声和台词 | 配对回复变体 | 按原配对关联，不各自随机 |
| 启动时段和工作提醒 | 对应插件推荐配置 | 转换触发规则，不导入旧状态机 |
| 随机互动与权重 | random-interaction 配置 | 保留意图，适配新冷却与调度 |
| 原触发器状态 | 场景参考和测试输入 | 映射为事件/条件/请求，不能直接控制渲染 |

第一轮只需要 idle、一个问候动作、一个有限动作、一段固定音声及休息/媒体基础模式；缺少某基础模式可先验证 fallback，但完整 Ema 行为验收必须补测实际素材。不能因少量动作播放成功就宣称原素材全部兼容。

### 10.2 最小素材与角色制作

系统运行的硬性最低素材是一张可显示的常规形态图片。人格可由作者填写，触发和声音均可为空。这个最低门槛只保证有效桌宠，不保证动作丰富或角色还原质量。

要复现某现有角色的全部视觉动作，需要相应帧素材或可产生相应动作的模型。agent 可从用户提供的立绘、三视图和表情参考辅助生成，但动作质量仍需逐项验证。希罗实验提供最小可行性的经验，不构成零加工、全动作精确复现的保证。

测试阶段两个实例可以使用同一 Ema 包，配置不同人格标记与独立 bank 来验证逻辑隔离，不必等待第二套美术素材。

## 11. 待原型确认的决策

| 决策 | 确认时机 | 验证依据 |
| --- | --- | --- |
| 技术栈、前端框架、工具版本 | P0/P1 | 透明窗口、焦点、播放和构建可行性 |
| 多组件单窗口或多个窗口 | P1 | 点击穿透、输入法、DPI、气泡定位 |
| 实例独立数据库或严格分区表 | P0/P2 | 隔离实现复杂度、迁移与查询测试 |
| 新消息默认等待还是主动中断 | P2 | 用户实际聊天体验，明确设置含义 |
| 默认 text-first 或 speech-synchronized | P2 | 首字延迟、音声衔接和阅读体验 |
| 阅读停留和正常生成长度 | P2 | 完整阅读与长任务等待之间的平衡 |
| 工作时长的默认统计口径 | P3 | 用户理解与实际设备活动证据 |
| 解包、队列和资源容量限值 | P0 初值，P5 定稿 | Ema 实测、异常样例和压力测试 |

这些开放项不阻止开始 P0，但不能悄悄当作用户已确认设置。影响设计原则的修改需重新讨论；实现细节的调整记录 ADR 与相应回归。

## 12. 编码顺序与交付纪律

建议按“共享契约 → 假实现调度 → 素材转换 → 新窗口与播放器 → 插件纵向闭环 → 统一 AI → 隔离与导出 → 完整功能 → 制作工具 → 发布验证”的顺序推进。

每个阶段将未完成项保留在其验收表中，不把未连接的按钮标成已完成。测试失败先修复对应边界，再扩大插件数量。协议变化同步更新样例、编辑器、宿主和迁移说明。

每次合并记录改变了什么、解决哪个场景、验证了什么以及仍有什么限制。阶段结束输出可运行构建、示例包、场景说明与验证证据。源码与文档都保存在本项目根目录下。
