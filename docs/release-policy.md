# 人工验收与不可变版本

公开仓库：[AyaseCompanion](https://github.com/ayasesakurashin-dotcom/AyaseCompanion)。P0/P1、P2 已通过人工实机验收，当前开发基线为 **v0.2.0**；首个正式基线 **v0.1.0** 的标签与附件保留。

## 阶段发布

1. 本机交付阶段候选程序与操作清单，用户实机验证；问题在同阶段修复和复验。
2. 用户明确确认阶段通过后，在本机保存源码、程序散列与验收关联，准备公开版本。
3. 检查公开源码及其历史，排除具体测试记录、私人路径、凭据和未授权素材；生产构建映射本机编译路径，再检查附件内容。
4. 推送源码和新标签，创建同名 GitHub Release，附上该版本独立程序、SHA-256 和功能范围说明。
5. 后续阶段从已验收标签继续开发，重复相同门槛。

辅助脚本 `tools/publish-verified.ps1` 校验忽略提交的本机验收文件、版本、当前提交、干净工作区、公开历史和标签不存在，再使用原子推送。它不会自动认定验收通过。凭据交由已登录的 Git 凭据管理器或连接器管理，不写入源码。

## 保留与回滚

- 每个后续版本基于之前的公开提交继续演进；标签固定源码，Release 固定程序。不 force push，不修改旧标签，不覆盖旧附件。
- 小修复使用 0.x.y 的补丁号；新增阶段使用新的 0.x.0。全部约定设计内容完成并验证后才发布 v1.0.0。
- 检出旧标签可恢复源码，下载对应 Release 可恢复应用文件。后续数据库升级需另行保留升级前数据备份。
- 角色包更新另外保留原包散列与引用；控制台“回退角色包”保持实例 ID，它独立于应用版本回滚。
- 首次公开版本以前的本机历史含私人验收信息，完整备份后仅留本机，不进入公共提交链。首次公开版本为干净根提交，后续版本均继承它。

## 公开边界

源码、通用设计与实现文档、自动测试实现、规则插件源码和生成通用样例的工具可公开。

实机批注、运行诊断、截图、具体测试结果、本机历史备份、个人路径、服务凭据和原应用数据仅留本机。原始素材与测试包保留在被忽略的 `local-assets/`、`artifacts/` 中。公开程序不附带 Ema 图像或音声。
