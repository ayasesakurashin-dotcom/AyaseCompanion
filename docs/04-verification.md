# 验证与验收方案

版本：0.1；日期：2026-10-26。

**本文为通用验证方案，不记录逐项实测结果。** P0/P1 已在 v0.1.0 完成人工实机验收；其他阶段继续按适用范围验证。原始批注与运行证据仅保存在本机。旧工程验证仅作为参考。

## 1. 验证层次与证据

| 层次 | 验证内容 | 能证明的范围 |
| --- | --- | --- |
| 协议与纯逻辑 | schema、合并、排序、假时钟、任务状态 | 逻辑确定性和输入约束 |
| 集成测试 | 包加载、插件解释、服务假实现、数据库、消息通道 | 模块边界和异常回收 |
| 桌面实机 | 透明窗口、DPI、输入法、全屏、媒体、音频设备 | 指定 Windows 环境的真实行为 |
| 实际服务 | AI 流、TTS、搜索、天气、记忆 bank | 已配置提供者的真实兼容性 |
| 体验验收 | 连贯性、阅读时间、设置理解和素材观感 | 用户是否认可实际使用效果 |

不使用随机联网结果验证纯调度；不以 mock 通过代替真实服务通过。固定种子、假时钟和可控服务用于复现竞态，真实环境用于验证平台行为。每条结果标记层次、构建版本、素材版本、环境和证据位置。

建议状态：待执行、通过、失败、阻塞、不适用。阻塞注明缺少的条件，不标为通过；不适用必须解释范围。已通过的结论仅对记录的版本成立。

## 4. 调度与非抢占

| ID | 场景 | 验收结果 | 阶段 |
| --- | --- | --- | --- |
| SCH-01 | 当前没有任务，连续提交不同优先级请求 | 排序按等级；同级按宿主入队序号 | P0 |
| SCH-02 | background 已开始，随后 important 到达 | background 整条完成才交接，不能在句末或页末抢占 | P0/P1 |
| SCH-03 | 同级 A 先入队但生成慢，B 后入队先准备好 | B 不超车；A 完成准备或准备失败/超时后才推进 | P0/P2 |
| SCH-04 | 低优先级仍准备，高优先级固定内容已就绪 | 高优先级可先开始；低任务结果不会直接播放 | P0/P2 |
| SCH-05 | 文字有三页、两段音声，动作时长不同 | 全部启用有限通道结束与最后阅读停留完成才释放 | P0/P2 |
| SCH-06 | 基础 idle/music 无限循环 | 不持有有限互动播放锁；下一任务可开始 | P0/P1 |
| SCH-07 | 任务尚未开始时 TTL 到期，另一个已开始后到期 | 前者过期跳过；后者完整执行 | P0/P1 |
| SCH-08 | 用户停止当前任务，随后旧文本/TTS/完成回调到达 | 立即取消，清空该任务缓冲；旧输出不能复活或影响下一任务 | P0/P2 |
| SCH-09 | 鼠标经过、打开输入框、输入草稿 | 不打断当前呈现；可按策略抑制新主动任务 | P0/P1 |
| SCH-10 | 多个通道几乎同时开始，回执乱序、重复或迟到 | 一份有效开始授权；一个最终任务结果；无双播 | P0/P1 |
| SCH-11 | 队首生成失败、流停滞、音频解码失败 | 有界失败/降级并释放所有权；下一任务可以执行 | P0/P2 |
| SCH-12 | 并发事件、系统时间回拨、插件伪造时间与 user 来源 | FIFO 不变；宿主分配顺序和来源，插件不能越权提级 | P0 |
| SCH-13 | 持续高优先级到达、重复触发和队列满 | 去重/冷却/限额生效；饥饿可诊断，不暗中改固定等级 | P3/P5 |
| SCH-14 | 全部页面阅读完成后气泡继续保留 | 已释放任务锁；新任务可按策略更新气泡 | P1/P2 |
| SCH-15 | 用户发送消息，分别选择等待和主动中断模式 | 各自严格按设置执行；未确认默认值有明确标记 | P2 |
| SCH-16 | 用户只静音，文字和动作仍有效 | 声音停止；其他通道正常收尾，不能错误取消整条任务 | P1/P2 |
| SCH-17 | 用户关闭或卸载正在执行的插件 | 撤销该实例订阅、基础请求和任务；其他插件不受影响 | P1/P3 |
| SCH-18 | 插件后台异常但已提交的呈现内容仍有效 | 不产生新请求；已有呈现仍完成，故障不冒充抢占 | P3/P5 |
| SCH-19 | starting 超时后旧播放器终于返回 started | 旧授权已失效，不能与新任务双播 | P0/P5 |
| SCH-20 | 一条生成回复持续输出但始终不结束 | 输出上限或故障收尾有界；无永久前台锁 | P2/P5 |

应使用可控音频与动画替身验证精确时序，再用实际 Ema 画面和音声复验。逻辑通过不证明 UI 没有漏掉一个旧回调。

## 8. 角色隔离、历史和长期记忆

远端测试只能使用本次新建、明确属于测试的实例和 bank；不得对现有用户 bank 做破坏性遗忘实验。测试标记使用不敏感的可辨识字符串。

| ID | 场景 | 验收结果 | 阶段 |
| --- | --- | --- | --- |
| MEM-01 | 同一包创建两个实例，分别输入不同测试事实 | instanceId、历史、摘要和记忆命名空间不同 | P2 |
| MEM-02 | 远端 provider 的存、取、同步分别操作两实例 | 请求指向各自 bank，无跨角色缓存和 outbox 串用 | P2 |
| MEM-03 | 改名、换外观、更新包版本 | 现有实例和记忆不变；新建副本则独立 | P2/P4 |
| MEM-04 | A 的生成/观察/摘要/同步未完成时切换 B | 不进入 B 的屏幕或存储，身份不依赖“当前全局角色” | P2 |
| MEM-05 | 候选已生成但过期未显示、部分显示后取消 | 前者不伪装成已发言；后者标记实际呈现部分 | P2 |
| MEM-06 | 摘要失败、重试及遗忘后旧摘要返回 | 水位只在成功提交时推进；旧 epoch 不能复活内容 | P2 |
| MEM-07 | 远端离线，本地聊天继续，再恢复同步 | 上下文可用；outbox 幂等，不重复写入或跨实例重试 | P2/P5 |
| MEM-08 | 导出角色并重新创建实例 | 包中无原实例 ID、bank、历史和密钥；新实例新记忆 | P2/P4 |
| MEM-09 | 对 A 执行清空历史、遗忘或删除实例 | 操作含义明确；B 与其他用户数据不变 | P2/P5 |
| MEM-10 | 主动问候、网页内容和 AI 猜测出现用户相关语句 | 不自动作为真实用户长期事实保存 | P2/P3 |
| MEM-11 | 查询当前屏幕与引用旧观察 | 时间、来源和引用正确，不把旧图当实时事实 | P3 |
| MEM-12 | 故意缺失 instanceId 的查询/写入或伪造外部 bank | 被存储/能力边界拒绝，不能退回公共默认 bank | P2/P5 |

隔离测试检查实际数据库、缓存键、请求日志和服务调用，而不只看 UI 是否显示不同昵称。

## 13. 阶段门槛与缺陷处理

- P0：核心协议和可控调度用例通过，正反例齐全，未决实现选择有 ADR。
- P1：离线纵向闭环及真实窗口、全屏、媒体初验通过，旧应用不作为运行依赖。
- P2：MVP-1—7 全部验证，真实 AI/TTS 可用，记忆隔离按本地/远端分别有证据。
- P3：默认功能目录全部有对应的操作和开关验证；实服务不足的项目明确阻塞。
- P4：普通用户通过工作台完成新建、插件配置、预览、导出和重新导入。
- P5：发布必要用例通过；关键隔离、播放抢占、数据丢失和崩溃恢复问题解决；性能达到已记录预算。
- P6：仅将实际完成独立验证的后端和插件运行时标为支持。

按场景风险选择自动测试：调度、身份、取消、导入事务和配置合并必须有回归；纯文案、可逆低影响样式调整以针对性检查为主，不为覆盖率数字编写镜像实现的测试。

实机问题用录屏、日志和复现配置定位。修复一个时序问题时，将最小竞态转成可控回归，再复验真实桌面。不反复运行无关全套测试来代替分析。

旧项目遗留构建问题不能成为新项目未通过检查的理由。新工程建立自己的构建、类型检查、格式校验和必要测试基线。
